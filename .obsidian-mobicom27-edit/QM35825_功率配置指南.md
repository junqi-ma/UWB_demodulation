# QM35825 雷达功率配置指南

## 概述

QM35825 UWB 芯片的雷达发射功率由**两层独立参数**共同控制：

| 层次 | 机制 | 接口 | 生效范围 |
|------|------|------|----------|
| 校准层 | `tx_power_index` / `debug.tx_power` / `pa_gain_offset` / `tx_power_control` | `cherry_set_calib()` | 全局持久化，设备复位后自动重载 |
| 会话层 | TX Profile 索引 | `cherry_radar_session_set_tx_profile_idx()` | 单次会话 |

雷达使用**天线组 3**（`RADAR_ANTENNA_SET = 3`，对应校准键前缀 `ant_set3.*`）。

---

## 一、会话层：TX Profile

`tx_profile_idx` 从设备内部 `lut_tx_profile` 中选择预设功率曲线：

| 值 | 宏定义 | 含义 |
|----|--------|------|
| `0x00` | `TX_PROFILE_HIGH` | 远距离，功率最大（**默认**） |
| `0x01` | `TX_PROFILE_LOW` | 近距离 |

命令行参数：`-i 0`（保持默认即可）。

---

## 二、校准层：功率相关校准键

### 2.1 键列表

| 键名 | 类型 | 范围 | 说明 |
|------|------|------|------|
| `ant<N>.ch5.ref_frame0.tx_power_index` | uint32 (4×uint8) | 每字节 0–254 | ch5 每帧 TX 功率 LUT 索引 |
| `ant<N>.ch9.ref_frame0.tx_power_index` | uint32 (4×uint8) | 每字节 0–254 | ch9 每帧 TX 功率 LUT 索引 |
| `ant<N>.ch5.pa_gain_offset` | int8 | -128–127 | ch5 PA 增益微调 |
| `ant<N>.ch9.pa_gain_offset` | int8 | -128–127 | ch9 PA 增益微调 |
| `ant_set<N>.tx_power_control` | uint8 位域 | 见下表 | 功率控制模式选择 |
| `debug.tx_power` | uint32 | 0–0xFFFFFFFF | debug 模式覆盖功率值 |
| `debug.pa_enabled` | bool | 0/1 | debug 模式下使能 PA |

### 2.2 tx_power_control 位域

| 位 | 名称 | 取值 | 说明 |
|----|------|------|------|
| Bit 0 | frame | 0/1 | 使用每帧功率索引（`tx_power_index`） |
| Bit 1 | post_tx | 0/1 | 使用 post-TX 功率索引 |
| Bit 2–6 | rfu | 0 | 保留 |
| Bit 7 | debug | 0/1 | 使用 debug 覆盖功率（`debug.tx_power`） |

常用值：

| 值 | 含义 |
|----|------|
| `0x01` | 仅 frame 模式（默认，通过 LUT 索引） |
| `0x03` | frame + post_tx 模式 |
| `0x80` | 仅 debug 覆盖模式 |
| `0x81` | frame + debug 叠加模式 |

---

## 三、三种功率配置策略

### 策略 A：Debug 覆盖模式（功率最大，推荐）

绕过 LUT 索引，直接将功率寄存器值写入硬件。

**修改文件**：`examples/utilities/include/util_calib_qm35825.h`

在第 272 行附近修改，并添加 debug 键：

```c
/* 修改 tx_power_control 为 debug 模式 */
CHERRY_CALIB_UINT8("ant_set3.tx_power_control", 0x80),

/* 添加 debug 功率键（在 ant_set3 之后） */
CHERRY_CALIB_UINT32("debug.tx_power", 0xFFFFFFFF),
CHERRY_CALIB_BOOL("debug.pa_enabled", true),
```

**原理**：`debug.tx_power` 直接映射到硬件功率寄存器，不经过固件 LUT 映射。

---

### 策略 B：最大化 LUT 索引

提高 `tx_power_index` 到 schema 上限，通过固件 LUT 映射到实际功率。

**修改文件**：`examples/utilities/include/util_calib_qm35825.h`

修改第 199–200 行和第 205–206 行：

```c
/* 修改前 */
CHERRY_CALIB_UINT32("ant0.ch5.ref_frame0.tx_power_index", 0x51515151),  // 81,81,81,81
CHERRY_CALIB_UINT32("ant0.ch9.ref_frame0.tx_power_index", 0x4d4d4d4d),  // 77,77,77,77
CHERRY_CALIB_INT8("ant0.ch5.pa_gain_offset", 0x5),
CHERRY_CALIB_INT8("ant0.ch9.pa_gain_offset", 0x8),

/* 修改后 */
CHERRY_CALIB_UINT32("ant0.ch5.ref_frame0.tx_power_index", 0xFEFEFEFE),  // 254,254,254,254
CHERRY_CALIB_UINT32("ant0.ch9.ref_frame0.tx_power_index", 0xFEFEFEFE),  // 254,254,254,254
CHERRY_CALIB_INT8("ant0.ch5.pa_gain_offset", 0x7F),                      // 127
CHERRY_CALIB_INT8("ant0.ch9.pa_gain_offset", 0x7F),                      // 127
```

同时确保第 272 行 `tx_power_control` 启用了 frame 模式：

```c
CHERRY_CALIB_UINT8("ant_set3.tx_power_control", 0x03),  // frame + post_tx
```

**注意**：最终功率受限于固件 LUT 内容。`tx_power_index` 只是索引，若 LUT[254] 未配置有效值，则无效。

---

### 策略 C：Frame + Debug 叠加（理论最大）

同时启用 LUT 索引和 debug 覆盖，两者叠加。

```c
CHERRY_CALIB_UINT8("ant_set3.tx_power_control", 0x81),  // frame + debug
CHERRY_CALIB_UINT32("debug.tx_power", 0xFFFFFFFF),
CHERRY_CALIB_BOOL("debug.pa_enabled", true),
CHERRY_CALIB_UINT32("ant0.ch5.ref_frame0.tx_power_index", 0xFEFEFEFE),
CHERRY_CALIB_UINT32("ant0.ch9.ref_frame0.tx_power_index", 0xFEFEFEFE),
```

## 四、QM35825 当前默认值与建议值对比

| 键名 | 当前默认值 | 建议最大值 | 修改位置（util_calib_qm35825.h） |
|------|------------|------------|-------------------------------|
| `ant0.ch5.ref_frame0.tx_power_index` | `0x51515151` (81) | `0xFEFEFEFE` (254) | 第 199 行 |
| `ant0.ch9.ref_frame0.tx_power_index` | `0x4d4d4d4d` (77) | `0xFEFEFEFE` (254) | 第 200 行 |
| `ant0.ch5.pa_gain_offset` | `0x05` | `0x7F` (127) | 第 205 行 |
| `ant0.ch9.pa_gain_offset` | `0x08` | `0x7F` (127) | 第 206 行 |
| `ant4.ch5.ref_frame0.tx_power_index` | `0x4a4a4a4a` (74) | `0xFEFEFEFE` (254) | 第 232 行 |
| `ant4.ch9.ref_frame0.tx_power_index` | `0x4a4a4a4a` (74) | `0xFEFEFEFE` (254) | 第 234 行 |
| `ant4.ch5.pa_gain_offset` | `0x07` | `0x7F` (127) | 第 231 行 |
| `ant4.ch9.pa_gain_offset` | `0x08` | `0x7F` (127) | 第 233 行 |
| `ant_set3.tx_power_control` | `0x01` | `0x80` (debug) | 第 272 行 |
| `debug.tx_power` | 不存在 | `0xFFFFFFFF` | 需新增 |
| `debug.pa_enabled` | 不存在 | `true` (1) | 需新增 |

> **注意**：radar_app 使用天线组 3，其 TX 天线路径为 `ant_set3.tx_ant_paths = {0x00, 0xFF}`（ant0），因此 ant0 的功率索引是雷达发射的主要控制项。ant4 的修改仅在其他天线组中生效。

## 五、功率加载流程

每次 `radar_app` 启动时，以下流程自动执行：

```
1. cherry_create()              ← 创建 Cherry 上下文
2. cherry_get_device_info()     ← 获取设备 ID 和封装信息
3. cherry_get_calib()           ← 从设备读回当前校准
     └─ check_calib()            判断 has_ant_set / has_lut_set
4. cherry_set_calib()           ← 将新校准写入设备（每次启动都执行）
     └─ 遍历所有校准键
     └─ 打包为 UCI 消息 (GID=0x0A, OID=0x2A)
     └─ 发送到 QM35 固件
     └─ 存储到 ctx->calib（设备复位时自动重发）
5. cherry_radar_session_start()  ← 启动雷达会话（使用 tx_profile_idx）
```

---

## 六、注意事项

1. **无绝对 dBm 值** — SDK 中不包含寄存器值到 dBm 的映射表，绝对功率需查阅 QM35 数据手册或联系 Qorvo 技术支持
2. **热管理** — 最大功率会产生更多热量，长时间运行注意芯片温度
3. **法规合规** — 不同地区的 UWB 发射功率有法规上限（FCC/ETSI 等），确保符合当地要求
4. **固件限制** — 最终功率上限由 QM35 固件决定，`tx_power_index` 只是 LUT 索引
5. **PA 使能** — debug 模式下必须设置 `debug.pa_enabled = true` 才能让 PA（功率放大器）工作，否则 `debug.tx_power` 无效
